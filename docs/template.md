# 文章模板

复制下面这段开始写。发布前删掉用不到的字段。

    ---
    title: 标题，必填
    description: 摘要。留空时自动从正文首段截取
    date: 2026-10-12
    cover: ./cover.jpg
    tags: [rust, 渲染]
    series: 系列名，可选
    draft: true
    ---

    正文从这里开始。

## 字段说明（决策 §13.6）

| 字段 | 必填 | 说明 |
|---|---|---|
| title | 是 | 标题 |
| date | 是 | 默认当前时刻；补写旧文时改成真实日期 |
| description | 否 | 摘要。留空时从正文首段截取 |
| cover | 否 | 封面，文件名相对本文目录。**没有就不写，不要为了凑图而放图** |
| tags | 否 | 必须来自 content/tags.json，否则构建会报错 |
| series | 否 | 系列名。同一系列的文章会自动出现「上一篇 / 下一篇」 |
| draft | 否 | 默认 false。为 true 时不生成页面，也不出现在任何列表、归档、标签、订阅里 |

**不存在的字段**：作者、语言、阅读量、序号。类型由目录决定，不需要写。

## 标签

标签必须先加进 content/tags.json 才能用（决策 §13.4）：

    ["rust", "bedrock", "渲染"]

这一点摩擦是有意的——**标签一旦分裂，合并成本随文章数增长**。
到了三百篇再想合并 rust 和 Rust，就得上百个文件一起改。

## 正文支持

标题、段落、代码块、图片、链接、列表、引用、表格、数学公式（$...$ 与 $$...$$）。

代码块的深浅两套配色跟随系统，不用手动指定。

## 发布

    git add content/
    git commit -m "post: 标题"
    git push

推送后由 CI 完成生成与部署。**或者直接在 GitHub 网页上编辑，效果一样。**
