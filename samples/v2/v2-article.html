用 Rust 重写 Bedrock 地图渲染器的三个月

从 C++ 迁移到 Rust 之后崩溃率降到了零，但真正的收获是那些在迁移过程中才暴露出来的设计问题——它们和语言无关。

一、崩溃消失了，但问题没有

内存错误被消灭了，但设计错误没有。Rust 帮我做到的只是前一半。迁移到第二周我就遇到了一个典型的例子：地图分块的加载和卸载是两套独立的逻辑，各自维护了一份引用计数。

编译器不能告诉你该怎么做，它只能告诉你现在这样做不通。剩下的是你自己的事。

最后的解法是把两个计数器合并成一个状态机，状态只有四种。改动本身只有几十行，但想明白它花了我四天。

二、性能反而是最简单的一环

出图是纯计算，没有 IO 等待，所以优化路径很直接：找到热点，减少分配，把递归改成迭代。

pub fn render_region(region: &Region) -> Tile {
    let mut tile = Tile::new(region.width, region.height);
    for chunk in region.chunks() {
        tile.blit(chunk.rasterize());
    }
    tile
}

整个渲染时间从 4.2 秒降到 0.8 秒，其中大约一半来自把逐像素写入改成按行写入。

三、代价

  • 编译时间从 6 秒涨到 40 秒，改一行要等一次链接
  • 团队里没人写过 Rust，前两周基本在查文档
  • 某些地方为了绕过借用检查写了不必要的克隆

但比起「凌晨三点被叫起来看 core dump」，这些都还算可以接受。
