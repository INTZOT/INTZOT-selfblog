用 Rust 重写 Bedrock 地图渲染器的三个月

从 C++ 迁移到 Rust 之后，崩溃率降到了零，但真正的收获是那些在迁移过程中才暴露出来的设计问题——它们和语言无关。

2026-10-12 · 18 分钟 · #rust #graphics

这个渲染器原本是 C++ 写的，三千多行，跑在服务端批量出图。它不算慢，但每隔几周就会因为某个野指针在凌晨崩一次，而我只能在第二天早上从 core dump 里倒推发生了什么。

把所有权交给编译器之后，我以为会轻松一些。确实轻松了，但真正花掉三个月的是另一件事。

一、崩溃消失了，但问题没有

Rust 帮我消灭的是内存错误，不是设计错误。迁移到第二周我就遇到了一个典型的例子：地图分块（chunk）的加载和卸载是两套独立的逻辑，各自维护了一份引用计数。C++ 时代这个设计靠约定活着，Rust 则直接拒绝编译。

编译器不能告诉你该怎么做，它只能告诉你现在这样做不通。剩下的是你自己的事。

最后的解法是把两个计数器合并成一个状态机，状态只有四种。改动本身只有几十行，但想明白它花了我四天。

二、性能反而是最简单的一环

出图是纯计算，没有 IO 等待，所以优化路径很直接：找到热点，减少分配，把递归改成迭代。

pub fn render_region(&self, region: &Region) -> Tile {
    let mut tile = Tile::new(region.width, region.height);
    for chunk in region.chunks() {
        // 分块之间没有依赖，可以并行
        tile.blit(chunk.rasterize());
    }
    tile
}

整个渲染时间从 4.2 秒降到 0.8 秒，其中大约一半来自把逐像素写入改成按行写入——这个改动在 C++ 版本里也能做，只是当时没人愿意碰那段代码。

三、代价

  • 编译时间从 6 秒涨到 40 秒，改一行要等一次链接
  • 团队里没人写过 Rust，前两周基本在查文档
  • 某些地方为了绕过借用检查写了不必要的克隆，性能其实还有余量

但比起「凌晨三点被叫起来看 core dump」，这些都还算可以接受。
